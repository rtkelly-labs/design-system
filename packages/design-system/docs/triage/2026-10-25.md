## The Diffra surface

Diffra's design goals:

- Typed evidence, trusted baselines, and deltas kept separate from policy.
- Static, self-contained HTML reports: no runtime JavaScript, CSP
  `default-src 'self'`.
- Time series with a candidate overlay (ADR 0007).
- Wide events and OTel spans for every run (ADR 0008).
- Benchmarks compared as distributions, with sample sizes and uncertainty
  (`VISION.md`).

### Already covered

- #423's `StatusMark` names Diffra's outcome, delta, evidence and trust
  vocabularies.
- #423's `ProvenanceStrip`, `DeltaValue`, `ChangeBar`, `KeyedDiff` and
  `DiffView` cover provenance and scalar or keyed change.
- #424's `ReviewReportPage` is the report a comparison tool emits.
- #419's `TraceWaterfall` and `TraceViewer` read OTLP, which is what ADR 0008
  emits.

### Built as experiments in `exp/e-diffra`

| Piece | What | Diffra goal |
|---|---|---|
| `githubRunToSpans` (`lib/ciTrace`) | A GitHub Actions run as a trace: run → queued → job → step. Stories on three runs captured from this repo | CI trace viewing; ADR 0008's "root span per workflow run" |
| `Flamegraph` (`lib/flame`) | Folded stacks or a trace as a flame graph or icicle; zoom, search, and a diff mode on the delta roles | Profiling evidence, and change in it |
| `BenchmarkCompare`, `DistributionCompare` (`lib/benchmark`) | Repeated samples compared with medians, confidence intervals and an explicit `inconclusive`; reads BenchmarkDotNet JSON | The distribution comparator `VISION.md` asks for |

### Still to do

1. **Static rendering.** ADR 0007 forbids runtime JavaScript in a report, but
   `TimeSeriesChart`, the waterfall and the flame graph are interactive React.
   A report-kit path is needed that renders each one to static SVG through
   `ds-report`; #424 adds the first template. This is the architectural
   question; settle it before adding more charts.
2. **Evidence chain view.** Show artifact → decoder → observation → comparator
   → delta → finding, for one finding. `VISION.md` requires reports to retain
   this chain.
3. **Intertwined history.** ADR 0008's main spine with PR candidates branching
   off at their merge-base, with metrics on it.
4. **Trend with candidate overlay.** ADR 0007: a metric along main, with the PR's
   value marked against it and a threshold band.
5. **Image comparison views.** Side by side, swipe, onion skin and difference,
   all from one comparison. Required by `VISION.md`'s acceptance list.
6. **CI trace tooling.**
   - `ds-trace`: a script that turns `gh api` run and jobs output into a trace
     file.
   - A live mode that polls an in-progress run through `useTraceClock`.
   - A critical-path summary in PR comments.

Each needs an issue in the #407 shape, with an epic over them. That's
drafted, but not filed until the owner says so.
