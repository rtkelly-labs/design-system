# Accessibility: what is measured, and what is not

Two gates run on every change, and they answer different questions. Knowing which is which
matters, because each is blind to what the other sees.

## Measured by arithmetic

`pnpm check:contrast` computes **222 pairs across two Levels** — every text role against every
ground it can sit on, every intent, every hue, and `text.inverse` against each accent it is
printed on. No browser, no rendering, no sampling.

It is strict in places WCAG is not. The palette floor is **5.5:1** rather than 4.5, because an
editor draws selection, current-line and find-match bands *behind* the same tokens: a palette
solved to exactly 4.5 has one sRGB step of headroom, and at 5.5 it has twenty-two.

## Measured by rendering

`pnpm test:a11y` runs axe over every asserted story, on both Levels — **162 assertions**. It
catches what arithmetic cannot: a missing accessible name, a scrollable region no keyboard can
reach, a role that contradicts the markup around it.

It found both of those on its first run. Two icon-only controls had no name, and three `<pre>`
blocks scrolled horizontally with no way to focus them — content simply unreachable without a
pointer.

## Measured by behaviour

Some failures are only visible across a whole task, not in any single story. `tests/a11y.spec.ts`
completes four account flows from the keyboard, and after every failed submit it checks what a
screen reader would hear.

**A form error is announced once.** `ErrorSummary` takes focus, and that is the announcement. A
field's `error` is not a live region: it is in the control's `aria-describedby` and marked with
`aria-invalid`, so it is read when a summary link moves focus to the field. Field errors used to be
`role="alert"`, so a four-error form read four alerts and then the same four messages in the summary
([#299](https://github.com/rtkelly13/design-system/issues/299)). The flow tests now fail if any live
region is carrying text when the summary takes focus, or if a field error describes no control.

## What neither catches

**`opacity` on text.** Contrast is computed from the *declared* foreground, and `opacity`
changes it afterwards. Three affordances sat at 3.45:1 and 2.64:1 on `sketch` — permanently,
on every touch device — while the gate reported every pair passing. They address `text.muted`
now, which is a role the gate can see.

**A composited ground.** A keyword over a selection band over a code well is neither a
contrast pair nor a separation distance, and no current gate has the shape to express it.
That is a known gap, written down rather than implied.

## The honest summary

Colour is measured and gated. Semantics are measured and gated. Composition of the two is
partly measured, and the gaps are named above rather than left for someone to discover.
